# 技能 03：內容配圖與圖像處理 SOP

這份文件規範了 AI 助理在處理「歷史文章配圖」任務時必須遵循的標準流程，確保網頁版面美觀且圖檔不會因外部連結失效而破圖。

## 核心原則：絕對禁止外部連結 (Hotlinking)
所有的圖片**必須**被下載並存放於專案本地端的 `images/` 資料夾內。絕對不可以在 Markdown 檔案中直接引用網際網路上的外部圖片網址（例如：`![圖說](https://wikipedia.org/xxx.jpg)` 是**嚴格禁止**的）。

## 核心原則二：入庫前必須壓縮（2026-07-21 新增）
> 背景：本專案曾累積 48 張未壓縮原圖（單張最大 20.1 MB、10000px 寬），使 `images/`
> 膨脹至 179 MB，嚴重拖慢行動裝置載入。已於 2026-07-21 全數壓縮（179 MB → 60 MB）。
> 為避免重蹈覆轍，**任何新圖片存入 `images/` 前必須符合以下規格**：

1. **尺寸上限**：長邊 ≤ **1600px**（網站文章區最寬約 900px，1600px 已保留足夠餘裕）。
2. **格式與品質**：照片、油畫、地圖類一律存 **JPEG，品質 82**，啟用 `optimize` 與 `progressive`；
   僅含透明背景或線條圖示者才使用 PNG。
3. **體積警戒線**：單檔超過 **500 KB** 即應重新檢視尺寸與品質設定；除極少數細節密集的
   大型地圖外，不應有超過 1 MB 的圖片入庫。
4. **壓縮方式**（Pillow 範例）：
   ```python
   from PIL import Image
   with Image.open(src) as im:
       im.thumbnail((1600, 1600), Image.LANCZOS)
       im.convert('RGB').save(dst, 'JPEG', quality=82, optimize=True, progressive=True)
   ```
5. 下載到的原始檔若超過規格，壓縮後**只保留壓縮版**入庫（原圖可經 git 歷史或原始網址取回）。

## 技能 A：主動配圖 (自動上網搜尋並插入)
當使用者要求為新文章或特定段落配圖時，AI 必須執行以下流程：
1. **閱讀與理解**：分析文章或段落的核心歷史事件、人物或器物。
2. **上網搜尋**：使用內建搜尋工具尋找符合歷史背景且具有公有領域 (Public Domain) 版權的圖片（如維基共享資源）。
3. **本地下載**：使用終端機指令（如 `curl` 或 `wget`）或 Python 腳本將圖片下載至本地的 `images/` 目錄中，並以具描述性的小寫英文命名（如 `images/p16_french_revolution.jpg`）。
4. **插入 Markdown**：在 Markdown 檔案 (`.md`) 合適的段落標題下方，使用原生語法插入圖片：
   `![這裡寫上詳細的歷史圖說，介紹圖片背景與意義](images/檔名.jpg)`
   *(系統在編譯時會自動將其轉換為專屬的 `<figure>` 左側圖說排版)*。

## 技能 B：被動配圖 (使用者提供圖片)
當使用者自行提供圖片或上傳圖片給 AI 時，AI 必須執行以下流程：
1. **視覺辨識**：理解該圖片的具體內容與涵義。
2. **位置判定**：掃描整篇文章，將該圖片安插在最具歷史關聯性的段落或 `##` 標題之下。
3. **檔案搬移**：若圖片尚未在 `images/` 資料夾內，必須協助將其移動至該目錄。
4. **插入 Markdown**：同技能 A，使用原生語法並附上精準的歷史圖說插入文本中。

## 系統架構須知
本專案的 `build_html_md.py` 已升級支援自動將原生 Markdown 圖片語法轉譯為高級網頁圖說排版。AI 無需去修改 Python 程式碼即可完成貼圖作業。
